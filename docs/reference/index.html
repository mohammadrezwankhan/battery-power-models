Native data flow

ThermalParameters supplies four constants. simulate validates the initial state and interval, then applies analytical_step to every current interval. constant_profile creates a count of equal-current intervals; the CLI divides the requested duration by that count before simulating. write_csv validates the complete trace before opening the destination. DC-link functions are independent of the thermal state and of each other. Thermal flow, DC-link functions.

There is no coupled electrical/thermal state estimator, battery state-of-charge solver, controller, measured-data loader, database or service API in the native modules. A proposed coupling belongs in a separately reviewed implementation change with explicit units, provenance and tests; it must not be inferred from similarly named browser teaching modes.

Browser data flow and persistence

The application reads an embedded JSON config, resolves four thermal parameter controls, and evaluates 241 uniformly spaced sample times from 0 to the configured 60-minute horizon. It draws the current trace and evaluates each lesson checkpoint at the checkpoint's own declared time. Playback advances model time faster than wall time and respects reduced-motion preference at initialization. The numerical library is exposed as window.LabSimulation; selected controller access is window.LabDashboard. Configuration and setup, controller.

Dashboard values and verification indicators live in memory. The portfolio page separately stores study notes, completed paths and motion preference in localStorage under a repository-and-source-revision key; its exported study plan says the guide did not execute the native models. The animation archive includes an illustrative waveform, not an additional native validation result. Portfolio persistence/export, archived waveform.

Python thermal API

Import from src.battery_thermal when the repository root is on Python's module search path, or add src explicitly as the existing tests do. There is no installed package/console entry point declared by this repository. The Python functions and the ThermalParameters constructor accept positional-or-keyword parameters. Default values make parameters optional; they do not change this calling convention.

Interface Contract and output
ThermalParameters(resistance_ohm=0.003, thermal_capacitance_j_per_k=5000.0, cooling_conductance_w_per_k=4.0, ambient_c=25.0) Frozen dataclass. Construction alone does not call validation. validate() returns None or raises ValueError; finite values, resistance >=0, capacitance and conductance >0.
analytical_step(temp_c, current_a, dt_s, params) -> float One constant-current analytical update; finite temperature/current/interval, interval >0; validates parameters and finite result.
simulate(currents_a, dt_s, params, initial_c=None) -> list[float] Uniform-interval sequence; output length is len(currents_a)+1, including the initial temperature. Default initial state is configured ambient. Valid empty input returns the initial state; invalid parameters/time/initial state still fail.
constant_profile(current_a, duration_s, dt_s) -> list[float] Repeats the finite current max(1, ceil(duration_s/dt_s)) times. Positive finite duration/interval required; rejects nonfinite or unrepresentable interval count. Returns only the profile, not an adjusted interval.
write_csv(path, currents_a, temperatures_c, dt_s) -> None path is a pathlib.Path; currents may be an iterable, temperatures a sequence. Materializes currents, validates shape/finite values/duration, then writes a UTF-8 CSV. Invalid input is rejected before opening the file. Valid writes overwrite it; filesystem errors propagate.
main() -> None Parses the thermal CLI and catches numerical ValueError as an argparse error. Ordinary filesystem errors and allocation errors are not caught by that handler.

Definitions: parameters, step, simulation, profile, CSV, CLI.

Thermal CLI and CSV

python src/battery_thermal.py [--current A] [--duration seconds]
    [--dt maximum_seconds] [--output path]

Defaults are 80 A, 900 s, maximum interval 1 s, and thermal_trace.csv. The CLI computes the number of intervals with constant_profile, then uses duration/count for every actual interval. Thus --duration 10 --dt 3 uses four 2.5-second intervals. --dt is a maximum for this CLI; passing 3 directly to simulate means exactly 3 seconds per interval. The CLI exposes no parameter-file, ambient, resistance or thermal-capacitance option. CLI implementation.

The header is time_s,current_a,temperature_c. Row zero records time 0, a current field of 0 by convention, and the initial temperature. Each later row records the interval-end time, current applied during that interval and resulting temperature rounded to six decimal places. The first current field is not a measured zero-current sample. Native CSV output differs from the browser's telemetry export. CSV format.

Python DC-link API

Signature Output and validation
triangular_current_ripple_vpp(current_pp_a, switching_hz, capacitance_f) -> float Voltage peak-to-peak in V. All finite; current >=0, frequency/capacitance >0; checks denominator representability and rejects nonzero-result underflow.
minimum_capacitance_for_energy_pulse(power_w, pulse_s, bus_v, allowed_drop_v) -> float Required ideal capacitance in F. All finite; power/time >=0, bus/drop >0, drop < bus; checks representability. Zero load or zero pulse gives zero when voltage/denominator constraints hold.

python src/dc_link.py prints two fixed examples. It has no argparse options or user-input sizing CLI; import the functions for other parameters. All numerical validation failures use ValueError. Functions and fixed demo.

MATLAB interfaces

battery_thermal_lumped(currents_a, dt_s, params, initial_c) returns a row vector with one more element than the numeric, real, finite current row vector. params is an optional scalar struct; omitted known fields receive the same defaults as Python, known fields are validated and converted to double, and additional fields do not alter the implemented equations. initial_c defaults to configured ambient. Range failures in the update raise BatteryPower:Range. Definition.

dc_link_ripple(current_pp_a, switching_hz, capacitance_f, power_w, pulse_s, bus_v, allowed_drop_v) takes seven scalar real finite doubles and returns a struct with ripple_vpp and minimum_capacitance_f. Both calculations execute in a single call, so inputs for both are required. Positivity/nonnegativity, drop and representability checks correspond to the Python relationships. There is no MATLAB CSV writer in these two model files. Definition.

Browser interfaces

The inline UMD library exports MODEL_SPECS, getModelSpec(kind), resolveParameters(kind, provided), evaluateModel(kind, provided, time), and checkCheckpoint(checkpoint, metrics). In a browser they are under window.LabSimulation. getModelSpec rejects unknown kinds. resolveParameters returns known parameter keys only: finite numeric inputs are clamped to declared ranges; missing/nonfinite/non-numeric inputs use the library default. evaluateModel clamps finite time into the model horizon and otherwise uses zero. The thermal result has temperatureC, heatRemovedW, storedEnergyKJ and residualW. Library.

checkCheckpoint returns a pass/fail/invalid result object. It accepts >=/gte, <=/lte, >/gt, </lt and equality aliases ==, =, eq, ≈; absolute tolerance affects equality and inclusive comparisons, while strict comparisons remain strict. Nonfinite metrics/expected values and unknown operators are invalid. Checkpoint logic.

window.LabDashboard is frozen and exposes getState(), evaluateModel and getModelSpec. The state snapshot includes kind, a copied params object, time, playing, activeMetric, and activeModule. Treat this as the source-observed browser interface, without assuming a published semantic-versioning guarantee. Export. The browser catalog accounts for all ten embedded model kinds; only thermal is selected by this repository's lesson config.

Lab 1: constant-current thermal response

python src/battery_thermal.py --current 80 --duration 900 --output thermal_trace.csv

Observed terminal result: Final temperature: 27.464 degC. Default resistance is 0.003 Ω, thermal capacitance 5000 J/K, cooling conductance 4 W/K and ambient 25 °C. Therefore heat is 19.2 W, steady temperature 29.8 °C and the time constant is 1250 s. The closed-form value at 900 s is approximately 27.4635891713921 °C; repeated one-second updates agree to floating-point precision, not bitwise identity. Defaults and update, CLI.

The CSV has an initial row plus 900 interval-end rows. Check that it begins at 25 °C, remains between 25 and 29.8 °C, and ends at 900 s. The initial current column is 0 by format convention; all subsequent interval currents are 80 A. The finite-temperature, monotonicity and sign-symmetry tests are useful regression checks, but they do not validate the parameter values against hardware. CSV writer, property tests.

Lab 3: cooling, current sign and custom initial temperature

python - <<'PY'
from src.battery_thermal import ThermalParameters, analytical_step, simulate
p = ThermalParameters()
print(analytical_step(40.0, 0.0, 600.0, p))
print(simulate([80.0, -80.0, 0.0], 60.0, p, initial_c=25.0))
PY

The first expression gives approximately 34.2817508770921 °C. Zero-current cooling approaches the configured ambient exponentially. Positive and negative currents of equal magnitude generate the same I²R heat in this model; the sign does not represent charging efficiency or reversible electrochemical heat. Each returned list includes the initial temperature. Update and sequence.

Lab 4: DC-link ripple and pulse energy

python src/dc_link.py

Observed output:

Triangular-current ripple: 0.1136 Vpp

Passing a voltage drop equal to the bus fails The energy calculation requires a positive final voltage: 0 < drop < bus. Choose inputs consistent with that modeled discharge boundary. Drop check.

Equations and derivations

Documentation snapshot: 2026-11-19. Implementation examined: 0304bfec25c43f42f103ebda239749b88609a187. Execution evidence and proposals are identified separately.

This document distinguishes literal implemented expressions from explanatory derivations. Values are reference inputs and synthetic fixtures; no measured calibration is established. Symbols and defaults are in parameters, and the domain boundary is in assumptions.

1. Lumped thermal balance

The native Python and MATLAB implementations correspond to the zero-dimensional energy balance

C_th dT/dt = I²R − G(T − T_a)
Q = I²R                    [W]
τ = C_th / G               [s]
T_ss = T_a + Q/G           [°C]

G denotes the code's cooling_conductance_w_per_k; the MATLAB comment calls it hA. C_th is total thermal capacitance in J/K, not electrical capacitance. A temperature difference in °C has the same numerical magnitude as a difference in K. I²R is nonnegative for either current sign, so this model omits sign-dependent reversible heat. Literal expressions are at Python update and MATLAB update.

Explanatory derivation. Hold I, R, G, C_th and ambient constant during one interval. Set θ = T − T_ss. Then dθ/dt = −θ/τ, so integration from one endpoint to the next gives

a = exp(−G Δt / C_th)
T_next = T_ss + (T_previous − T_ss) a

That is the expression the code evaluates, rather than a forward-Euler approximation. For positive G, C_th and Δt, the mathematical factor satisfies 0 < a < 1; roundoff may give exactly 0 or 1 at extreme scales. The mathematical update lies between the previous temperature and steady temperature. There is no Euler-style stability timestep restriction for this held-input equation. A rapidly varying physical current still requires an appropriate piecewise-constant input representation. Step and sequence.

Initial and boundary conditions

simulate stores T(0)=initial_c, defaulting to the configured ambient. The ambient is a constant thermal reservoir coupled through G; when T is below ambient, G(T−T_a) is negative and heat enters the lump. This is a spatially uniform model, so there are no spatial mesh, surface-flux or PDE boundary nodes. For the audited implementation, G=0 is supported by the exact adiabatic branch, T_next = T_now + I²R Δt/C_th; the historical source snapshot linked in this section predates that remediation. Validation and initial state, simulation.

Native discretization and CLI duration

Each current in simulate applies for the same supplied Δt, and the result has N+1 endpoints. The CLI computes N=max(1,ceil(duration/requested_dt)), then Δt=duration/N. Direct API users must choose their own interval explicitly; constant_profile does not return a corrected time step. No adaptive tolerance, nonlinear iteration or numerical ODE solver is used. Profile and CLI, CLI integration.

2. Active browser thermal lesson

The selected browser mode implements the same constant-source balance with direct heat input Q and the fixed initial condition T(0)=T_a:

t_s = 60 t_min
ΔT(t) = (Q/G) [1 − exp(−G t_s/C_th)]
temperatureC = T_a + ΔT
heatRemovedW = G ΔT
storedEnergyKJ = C_th ΔT / 1000
residualW = Q − G ΔT

residualW is the instantaneous heat-storage rate, not an integrated conservation-error diagnostic. storedEnergyKJ is sensible thermal energy relative to the initial ambient, not battery electrical state of energy. The dashboard config overrides the library's generic defaults and selects minutes/60-minute horizon; the native Python defaults use seconds and different constants. Implemented browser branch, active config. The other nine browser modes are separate teaching proxies cataloged in browser models.

3. Triangular capacitor-current ripple

Literal implementation:

ΔV_pp = I_pp / (8 f_sw C_dc)

Here I_pp is the peak-to-peak value of a symmetric, zero-mean triangular capacitor current; it is not automatically the bus DC current, RMS current or inductor ripple for an unspecified topology. Python, MATLAB.

Explanatory derivation. The positive current half-cycle has duration 1/(2f_sw) and peak I_pp/2. Its triangular charge area is (1/2) × (1/(2f_sw)) × (I_pp/2) = I_pp/(8f_sw). The ideal capacitor's voltage changes by ΔQ/C_dc between the two current zero crossings, giving peak-to-peak ripple above. Units are A/(s⁻¹ F)=V. This derivation assumes periodic zero-mean current and an ideal capacitor; it does not include instantaneous ESR ripple or ESL voltage.

4. Capacitance for a constant-power energy pulse

Literal implementation uses a factored energy denominator:

E_pulse = P Δt_p
V_initial = V_bus
V_final = V_bus − ΔV
C_min = 2 P Δt_p / [ΔV (2 V_bus − ΔV)]

Explanatory derivation. Equate pulse energy to the capacitor energy decrease:

P Δt_p = (1/2) C_dc [V_bus² − (V_bus − ΔV)²]
V_bus² − (V_bus − ΔV)² = ΔV (2V_bus − ΔV)

Solving gives the implemented C_min. The factored form avoids subtracting two nearly equal squared voltages, but it does not eliminate every floating-point overflow/underflow case. Inputs require P>=0, duration>=0 and 0 < ΔV < V_bus; thus this branch describes discharge over an allowed positive drop, not negative-power charging. The capacitor supplies the ideal pulse alone; source replenishment and losses are absent. Units are J/V²=F. Python energy calculation, MATLAB, small-drop regression.

5. Numerical agreement and what it establishes

Python uses finite floating-point checks and the MATLAB functions convert/model inputs as doubles. Extreme finite inputs can still make intermediate denominators or final values unrepresentable. The thermal expression can lose tiny changes by cancellation; neither its “analytical” name nor full branch coverage establishes arbitrary-precision accuracy. Native bounds tests explicitly exercise overflow, underflow and invalid traces. Boundary tests.

The cross-language regression criterion is abs(actual−expected) <= 1e-12 + 1e-12 * abs(expected) for each fixture value. These tolerances describe deterministic fixture comparison, with units inherited from each metric, not uncertainty from measurement or parameter identification. MATLAB execution and fixture provenance must be reported separately. Python capture, MATLAB parity comparison.

Naming collisions and conversions

  • C_th is thermal capacitance in J/K; C_dc is electrical capacitance in F. Code field names preserve this distinction even when a generic browser parameter is called capacityJPerK.
  • G and the MATLAB comment's hA mean the same total W/K conductance. A value of h in W/(m²·K) alone cannot be substituted without an area.
  • Native Δt is in seconds; browser thermal time is in minutes and is multiplied by 60 internally. Browser storedEnergyKJ divides joules by 1000.
  • Native current may be signed, but thermal heat uses its square. DC-link current_pp_a is nonnegative peak-to-peak ripple, not that signed current.
  • ΔV in energy sizing is a one-direction bus-voltage drop; ΔV_pp is full periodic ripple. They have the same unit and different meanings.

These mappings follow the expressions in native thermal, native DC-link and browser thermal. Preserve identifiers in code and document aliases explicitly when comparing repositories.

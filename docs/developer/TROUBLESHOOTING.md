## When a check fails remotely

Identify the PR head SHA, provider, workflow run, job and actual tested SHA first. Read the failing job's logs and confirm whether the revision is the head, a synthetic PR merge or a merge-queue commit. A historical green source check does not clear a new documentation candidate. The metadata policy workflow checks author/committer/commit-message data in an event-selected revision range; inspect its actual failure messages and checked-commit summary. The workflow does not print the selected range as a separate diagnostic line. [Authorship policy](https://github.com/mohammadrezwankhan/battery-power-models/blob/0304bfec25c43f42f103ebda239749b88609a187/.github/workflows/no-codex-attribution.yml#L25-L103).

Do not weaken checks or falsify metadata to obtain a green result. Record the failing condition and follow [the release playbook](../maintainer/CI_CD_AND_RELEASE_PLAYBOOK.md). If the classic protection API is inaccessible, that is a permission limitation, not evidence that review, signature or queue rules are absent.
